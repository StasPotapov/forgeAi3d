# forgeAi3d

[English](README.md) · **Русский**

Воркспейс для моделирования деталей под 3D-печать **вместе с AI-агентом**.

Своего CAD здесь нет. forgeAi3d — сборка чужих проектов: CAD-ядро, справочник крепежа,
анализатор печатопригодности, рендерер, библиотеки для работы с мешами. Они связаны
в один цикл и обёрнуты в CLI так, чтобы агент вызывал их сам, читал вывод и делал по
нему следующий шаг: обмерить деталь, посмотреть на превью, поправить константу. Знание
о том, что и когда вызывать, лежит в скилле — полный состав в таблице ниже.

Идея простая: модель — это Python-файл, а не проект в GUI. Значит агент видит её целиком,
правит точечно и версионирует. Ты говоришь, что нужно, — получаешь STL, превью и отчёт
о печатопригодности. Печатаешь, говоришь что не так — правится одна константа.

```
описание задачи → models/деталь.py → prints/деталь/деталь.stl → печать
                        ↑                                       │
                        └── «отверстие мало на полмиллиметра» ───┘
```

![контактный лист калибровочной гребёнки](docs/fit_test.png)

## Из чего собрано

Свой код здесь тонкий: профиль принтера и справочник филаментов (`forge/`), четыре
CLI-обёртки (`tools/`) и скилл. Всю тяжёлую работу делают вот эти проекты.

| Инструмент | Зачем здесь |
|---|---|
| [build123d](https://github.com/gumyr/build123d) | CAD-ядро. Деталь описывается кодом на Python, геометрия — B-Rep поверх OpenCascade: настоящие фаски, скругления и экспорт в STEP |
| [OCP](https://github.com/CadQuery/OCP) | Python-биндинги [OpenCascade](https://github.com/Open-Cascade-SAS/OCCT), ядро под build123d. `measure.py` обращается к нему напрямую — читает типы поверхностей и по ним отличает отверстие от штыря и скругления |
| [bd_warehouse](https://github.com/gumyr/bd_warehouse) | Готовый крепёж к build123d: винты, гайки, подшипники, резьбы по стандарту. Чтобы размеры M3 не сочинялись по памяти |
| [augura](https://github.com/pzfreo/augura) | Проверка печатопригодности по STEP — свесы, мосты, толщина стенок, опрокидывание, подбор позы. По точным граням тела, а не по треугольникам |
| [trimesh](https://github.com/mikedh/trimesh) | Всё, что про меши: загрузка STL, герметичность, нормали, лучевые запросы (толщина, внутренние пустоты), правка чужих моделей |
| [manifold3d](https://github.com/elalish/manifold) | Бэкенд булевых операций для trimesh — без него вычитания и объединения на мешах разваливаются |
| [rtree](https://github.com/Toblerity/rtree) | Пространственный индекс, на нём держатся быстрые лучевые запросы trimesh |
| [numpy](https://github.com/numpy/numpy) | Массивы вершин и нормалей, вся геометрическая арифметика в проверках и подсветке свесов |
| [networkx](https://github.com/networkx/networkx) | Граф связности треугольников в `solidify.py`: так находятся внутренние оболочки и кромки, которые потом заклеиваются |
| [Pillow](https://github.com/python-pillow/Pillow) | Обрезка полей у рендеров и сборка видов в один контактный лист |
| [OpenSCAD](https://github.com/openscad/openscad) | Headless-рендер PNG и булев разрез детали. Единственная внешняя программа — остальное пакеты Python |
| [uv](https://github.com/astral-sh/uv) | Зависимости и запуск: `uv run` вместо ручных venv |
| [Claude Code](https://github.com/anthropics/claude-code) | Агент, под которого написан скилл из `skill/` — что вызвать, как прочитать вывод и что править дальше. Формат его, но содержимое обычный markdown: другой агент переучивается на него одной просьбой |

## Зачем, если есть GUI-редакторы

GUI-редактор с MCP заставляет агента кликать в чужом интерфейсе: он не может отдать файл
и не может принять твой STL иначе как массивом координат. Здесь наоборот — файл на входе,
файл на выходе, а между ними текст, который агент читает и правит.

Побочная выгода: параметры детали становятся именованными константами. «Сделай стенку
потолще» — это правка одной строки, а не перерисовывание модели.

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и OpenSCAD.

```bash
git clone git@github.com:StasPotapov/forgeAi3d.git ~/dev/forgeAi3d
cd ~/dev/forgeAi3d
uv sync
```

OpenSCAD на macOS — **именно snapshot-каск**, стабильный `openscad` это сборка 2021.01
под Intel, и macOS ругается на неё:

```bash
brew install --cask openscad@snapshot
```

На Linux — `apt install openscad` или пакет дистрибутива. Инструменты ищут бинарь
`openscad` в `PATH`, на macOS дополнительно смотрят в `/Applications`.

Репозиторий может лежать где угодно: путь берётся от самого пакета, а переопределяется
переменной `FORGEAI3D_HOME`.

## Быстрый старт

```bash
uv run python models/fit_test.py                                  # -> prints/fit_test_pla/
uv run tools/measure.py prints/fit_test_pla/fit_test_pla.stl         # размеры и отверстия числами
uv run tools/preview.py prints/fit_test_pla/fit_test_pla.stl         # контактный лист
uv run tools/check.py prints/fit_test_pla/fit_test_pla.stl --material PLA   # печатать или нет
```

Инструментам достаточно пути к STL: STEP для точного анализа они находят сами.

`models/fit_test.py` — калибровочная гребёнка: десять отверстий под M3 с зазорами
от 0.00 до 0.45 мм на сторону. С неё стоит начать (см. «Калибровка» ниже).

## Два примера из жизни

### Дюбель под шуруп — сделан по описанию

Задача была поставлена словами: нужен мебельный дюбель в отверстие 5 мм под шуруп
3.5×15. Три числа дал я, остальное агент решил сам и назвал вслух: PETG, потому что
вязкий и терпит распор; посадка `press`, потому что дюбель забивают; кольцевые зубцы
вместо классических распорных лепестков — при стенке около миллиметра печатные лепестки
ломаются по слоям; бортик 6 мм, чтобы спрятался под шляпкой шурупа 7 мм.

![дюбель в разрезе](docs/dowel.png)

Дальше начался тот самый цикл. Первая версия в отверстии провернулась: кольцевые зубцы
держат от выдёргивания, но против кручения осесимметричному телу цепляться нечем — шуруп
таскал дюбель за собой вместо того, чтобы вкручиваться. Из одной фразы «прокручивается»
получилась переделка: сквозная прорезь вдоль тела (половинки расходятся и распирают
дюбель в отверстии), четыре продольных ребра против проворота и пилотное отверстие шире
на 0.3 мм — чтобы шуруп нарезал резьбу, а не срывал деталь с места.

Модель — `models/dowel_5mm.py`, и всё в ней крутится константами: `BARB_OVER` — насколько
зубцы выступают за тело, `RIB_COUNT` и `RIB_OVER` — число и вылет рёбер, `PILOT_TOP`
и `PILOT_BOT` — внутренний конус, по которому шуруп идёт всё туже, `SLOT_W` и `SLOT_ANG` —
ширина и раскрытие прорези. Печатается стоя на A1 mini.

### Клинок из игрушки — заполнена чужая модель

Второй случай — не моделирование, а правка присланного STL. Витой клинок игрушечной
катаны оказался полой трубой со стенкой около 1.2 мм: слайсер честно видит полость и
печатает её пустотой, деталь выходит хрупкой. Нужно было сделать её сплошной, не тронув
внешнюю форму.

```
$ uv run tools/solidify.py катана.stl
катана.stl: 5161 мм³, найдено внутренних пустот: 1
  [1]  1496 треугольников, площадь 4013.6 мм², габарит 11.2×9.7×168.8 мм, открытых рёбер 42

$ uv run tools/solidify.py катана.stl --fill 1
убрано внутренних треугольников: 1496 из 3726
объём: было 5161 мм³ → стало 11335 мм³
```

Наружные треугольники взяты из исходника как есть, поэтому витой профиль и острые рёбра
остались прежними. Объём вырос вдвое — дальше тем, что внутри, распоряжается слайсер.

## Настройка под свой принтер

Всё железо и все пластики описаны в одном файле — **`forge/spec.py`**. Из коробки там
Bambu Lab A1 mini и пластики PLA + PETG.

```python
A1_MINI = Printer(
    name="Bambu Lab A1 mini",
    bed=(180.0, 180.0, 180.0),
    nozzle=0.4,
    extrusion_width=0.42,   # ширина линии периметра
    layer_height=0.2,
    enclosed=False,         # нет закрытой камеры -> ABS/ASA не поедут
    hardened_nozzle=False,  # нет закалённого -> абразивные не поедут
    ams=False,
    bed_slinger=True,       # стол ездит по Y -> высокие детали качает
)

AVAILABLE = ("PLA", "PETG")   # что реально лежит на полке
```

Опиши свой принтер и держи `AVAILABLE` в актуальном состоянии — проверки начнут
ругаться на несовместимые материалы сами.

## Как этим пользуются модели

Вместо магических чисел — вызовы из `forge`:

```python
from forge import clearance, wall, compensate_shrink, export_all

MAT = "PETG"
shaft_hole = 8 + 2 * clearance(MAT, "slip")   # 8.6 мм; на PLA было бы 8.4
case_wall  = wall(3)                          # 1.26 мм = 3 периметра, а не «1.5 мм»
length     = compensate_shrink(150, MAT)      # 150.9 мм с поправкой на усадку

export_all(part.part, "деталь", material=MAT) # stl + step + 3mf, запись проверена
```

Типы посадки: `press` (запрессовка), `snug` (с усилием руки), `slip` (свободно ходит),
`free` (заведомо с люфтом). Зазор задаётся **на сторону**, отверстие получает удвоенный.

Помимо PLA и PETG в справочнике заведены `PLA-CF`, `ASA` и `TPU` — чтобы `supported()`
называл причину, когда материал не подходит принтеру (ASA без закрытой камеры, PLA-CF
без закалённого сопла), а не выдумывал зазор молча.

Размеры чужого железа, которые нельзя обмерить руками, ищутся в datasheet и кладутся
в кэш вместе с источником — число без ссылки не сохраняется:

```python
from forge import get_spec, save_spec
save_spec("raspberry pi 5", {"length": 85.0, "width": 56.0},
          source="https://datasheets.raspberrypi.com/rpi5/raspberry-pi-5-mechanical-drawing.pdf")
```

## Что появляется на выходе

У каждой детали своя папка. На виду — только STL, который несут в слайсер; всё
остальное убрано в `extras/`, чтобы не искать нужный файл среди служебных:

```
prints/подставка/
    подставка.stl                     ← это и печатают
    extras/подставка.step             ← правки в CAD и точный анализ
    extras/подставка.3mf              ← Bambu Studio: миллиметры, имя, материал
    extras/подставка.png              ← превью
    extras/подставка-overhangs.png    ← свесы красным
    extras/подставка-section-y.png    ← разрез
```

## tools/measure.py

Отвечает на вопрос «получилось ли то, что просили» числами, а не картинкой.

```bash
uv run tools/measure.py prints/part/part.stl
uv run tools/measure.py prints/part/part.stl --json
```

Печатает габариты, объём, число тел и разбор круглых элементов: отверстия с диаметром,
глубиной и координатами центров, штыри, скругления и галтели. Одинаковые схлопываются
в `4 × Ø3.40`. Отверстие называется сквозным по геометрии, а не по габариту детали —
фаска или выступающая надпись сдвигают габарит и путают такую проверку.

## tools/preview.py

Рендерит STL в PNG через headless OpenSCAD и собирает виды в один контактный лист.
Нужен, чтобы агент посмотрел на результат до того, как отдать файл.

```bash
uv run tools/preview.py prints/part/part.stl                        # iso, top, front, right
uv run tools/preview.py prints/part/part.stl --overhangs --material PETG
uv run tools/preview.py prints/part/part.stl --section y            # или y:12.5
uv run tools/preview.py prints/part/part.stl -o /tmp/p.png --size 800
```

Без `-o` картинка ложится в `extras/` этой детали, имя получает суффикс режима.
`--size` задаёт разрешение рендера: готовый кадр обрезается по детали, поэтому
тайл выходит меньше запрошенного.

Виды: `iso`, `iso2`, `iso3`, `iso4` (изометрия с четырёх сторон), `top`, `front`,
`right`, `back`, `iso_low`, `bottom`.

`--overhangs` красит красным всё, что придётся поддерживать, и сам переключается
на нижние ракурсы — сверху свесы не видно:

![подсветка свесов](docs/overhangs.png)

`--section` разрезает деталь и показывает внутренности: толщину стенки иначе
не проверить, не напечатав деталь. Плоскость среза красится оранжевым, а ракурсы
берутся со стороны отрезанной половины — иначе в кадре целая деталь:

![дюбель в поперечном разрезе](docs/section.png)

## tools/check.py

Проверяет деталь перед печатью.

```bash
uv run tools/check.py prints/part/part.stl --material PETG
uv run tools/check.py prints/part/part.stl --nozzle 0.6 --bed 256x256x256
uv run tools/check.py prints/part/part.stl --no-orientation    # пропустить подбор позы
```

Геометрию считает [augura](https://github.com/pzfreo/augura) — по точным граням тела,
а не по треугольникам: свесы, мосты, толщина стенок, опрокидывание, brim, влезает ли
на стол, минимальная вертикальная ступенька (она же максимальная высота слоя). Плюс
перебирает позы и предлагает ту, где неподдержанных свесов меньше.

По толщине augura отдаёт минимум, а браком деталь становится по **доле поверхности**
тоньше двух периметров: у фаски, уклона и у кромки выдавленной буквы толщина по
построению стремится к нулю, и по одному минимуму в брак уходила бы любая деталь
с надписью. Минимум остаётся в отчёте справкой.

Если на входе STL, рядом ищется одноимённый STEP и анализ идёт по нему. Без STEP
проверка приблизительная: **толщина стенок и мелкие детали по мешу не считаются**,
и отчёт об этом честно говорит.

Качество самого меша (герметичность, нормали, вырожденные треугольники, число тел)
проверяется по STL — это то, чего в STEP не бывает по определению.

**Код возврата 1** — печатать не стоит: негерметичный меш, тонкая стенка, деталь
опрокинется, не влезает на стол ни в одной ориентации, материал несовместим с принтером.
Если деталь влезает после поворота на 90° в плоскости стола, это предупреждение,
а не отказ: augura меряет габарит по осям как есть, а на стол кладут как удобно.

**Предупреждения на код возврата не влияют** — они зависят от ориентации детали,
а её выбирают уже в слайсере: свесы, brim, рекомендация развернуть.

## tools/solidify.py

Заливает внутреннюю полость в чужом меше. Полая модель (труба, вазовый режим,
отсканированная скорлупа) печатается пустой: слайсер честно видит полость и не кладёт
внутрь инфилл.

```bash
uv run tools/solidify.py присланная.stl                          # показать, что внутри
uv run tools/solidify.py присланная.stl --fill 1     # -> prints/присланная_solid/
```

Сначала инструмент показывает найденные пустоты — сколько треугольников, площадь,
габарит и сколько у пустоты открытых рёбер (ноль означает замкнутую полость):

```
katana_orig.stl: 5161 мм³, найдено внутренних пустот: 1
  [1]  1496 треугольников, площадь 4013.6 мм², габарит 11.2×9.7×168.8 мм, открытых рёбер 42
```

**Что заливать, решает человек.** Отличить полость от сквозного отверстия
автоматически нельзя: по лучу стенка отверстия выглядит такой же внутренней, а у
трубы полость сама открыта торцом. Поэтому без `--fill` файл не пишется вовсе —
инструмент не станет молча закрывать отверстия под винты.

Выбранная оболочка срезается, кромка заклеивается веером от центроида. Внешняя
геометрия не трогается — берутся ровно исходные треугольники наружной поверхности,
поэтому профиль и острые рёбра сохраняются 1:1.

## Скилл для агента

Скилл учит агента работать по этому циклу: сверять размеры числами, обязательно смотреть
на превью, гонять проверку перед выдачей, брать зазоры из `forge`, а не выдумывать, искать
размеры чужого железа в datasheet вместо того чтобы их сочинять, и править константу вместо
пересборки модели. Внутри — шпаргалка по API build123d и bd_warehouse (каждый пример
исполнен, а не написан по памяти) и правила проектирования под FDM.

Лежит в двух вариантах, содержание одинаковое: `skill/en/forgeAi3d` (английский)
и `skill/ru/forgeAi3d` (русский). Ставится один — тот, на языке которого удобнее читать:

```bash
ln -s ~/dev/forgeAi3d/skill/en/forgeAi3d ~/.claude/skills/forgeAi3d   # или skill/ru/forgeAi3d
```

Дальше он подхватится сам по контексту или вызывается как `/forgeAi3d <что нужно>`.

**Формат — Claude Code, но привязки к нему нет.** Внутри обычный markdown: инструкции,
таблицы и справочники. Работаешь с другим агентом — попроси его переписать `SKILL.md`
и `references/` в тот формат, который он понимает; правила и числа переедут как есть,
поменяется только обёртка. Примеры установки и вызова в этом файле — под Claude Code.

Скилл универсален: конкретное железо он берёт из `forge/spec.py`, а не из своего текста.

## Калибровка

Зазоры и усадка в `forge/spec.py` — типовые практические значения, а не паспортные
константы. Они зависят от катушки, влажности и профиля печати.

Чтобы получить свои: поменять `MAT` в `models/fit_test.py`, напечатать по гребёнке
на каждый пластик (материал подписан на детали и попадает в имя файла), вставить винт M3
в каждое отверстие и найти два номера — где винт входит с усилием руки (`snug`) и где
ходит свободно без люфта (`slip`). Отверстие N имеет зазор `0.05 * N` на сторону,
диапазон 0.00–0.45 покрывает все четыре посадки.
Полученные числа вписать в `clearances` соответствующего материала.

## Чем это отличается от MCP-серверов для CAD

Рядом живут [build123d-mcp](https://github.com/pzfreo/build123d-mcp),
[agentcad](https://github.com/jdilla1277/agentcad) и
[cad-agent](https://github.com/Svetlana-DAO-LLC/cad-agent) — они дают агенту CAD-сессию
и набор инструментов внутри неё.

forgeAi3d устроен иначе:

- **деталь — файл в репозитории**, а не состояние сессии. Её видно в git, к ней можно
  вернуться через полгода и поменять одну константу;
- **профиль принтера — исполняемый код**, а не абзац в инструкции. `wall(3)` знает
  ширину линии, `clearance()` знает пластик, `supported()` знает, что ASA здесь не поедет;
- **цикл не заканчивается экспортом**. Самая частая работа — «напечатал, отверстие мало»,
  и она описана в скилле отдельно.

Ничто не мешает пользоваться и тем и другим: MCP-сервер — для лепки геометрии в диалоге,
forgeAi3d — когда деталь нужно хранить, повторять и допиливать по итогам печати.

## Структура

```
models/    исходники деталей (.py, build123d)
forge/     параметры принтера, справочник филаментов, экспорт, кэш найденных размеров
tools/     preview.py — рендер, check.py — проверка, measure.py — обмер, solidify.py — заливка полостей
skill/     скилл для агента: en/ и ru/, содержание одинаковое
scripts/   sync-skill.sh — синхронизация скилла с ведущей копией
docs/      картинки для этого файла
prints/    по папке на деталь: STL на виду, остальное в extras/ (в .gitignore)
```
