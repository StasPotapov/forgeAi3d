# forgeAi3d

[English](README.md) · **Русский**

Воркспейс для моделирования деталей под 3D-печать **вместе с AI-агентом**.

Своего CAD здесь нет. forgeAi3d — сборка чужих проектов: CAD-ядро, справочник крепежа,
анализатор печатопригодности, рендерер, библиотеки для работы с мешами. Они связаны
в один цикл и обёрнуты в CLI так, чтобы агент вызывал их сам, читал вывод и делал по
нему следующий шаг: обмерить деталь, посмотреть на превью, поправить константу. Знание
о том, что и когда вызывать, лежит в скилле — полный состав в таблице ниже.

Идея простая: модель — это Python-файл, а не проект в GUI. Значит агент видит её целиком,
правит точечно и версионирует. Ты говоришь, что нужно, — получаешь STL, превью и отчёт
о печатопригодности. Печатаешь, говоришь что не так — правится одна константа.

```
описание задачи → models/деталь/model.py → models/деталь/деталь.stl → печать
                        ↑                                       │
                        └── «отверстие мало на полмиллиметра» ───┘
```

## Из чего собрано

Свой код здесь тонкий: профиль принтера и справочник филаментов (`forge/`), пять
CLI-обёрток (`tools/`) и скилл. Всю тяжёлую работу делают вот эти проекты.

| Инструмент | Зачем здесь |
|---|---|
| [build123d](https://github.com/gumyr/build123d) | CAD-ядро. Деталь описывается кодом на Python, геометрия — B-Rep поверх OpenCascade: настоящие фаски, скругления и экспорт в STEP |
| [OCP](https://github.com/CadQuery/OCP) | Python-биндинги [OpenCascade](https://github.com/Open-Cascade-SAS/OCCT), ядро под build123d. `measure.py` обращается к нему напрямую — читает типы поверхностей и по ним отличает отверстие от штыря и скругления |
| [bd_warehouse](https://github.com/gumyr/bd_warehouse) | Готовый крепёж к build123d: винты, гайки, подшипники, резьбы по стандарту. Чтобы размеры M3 не сочинялись по памяти |
| [augura](https://github.com/pzfreo/augura) | Проверка печатопригодности по STEP — свесы, мосты, толщина стенок, опрокидывание, подбор позы. По точным граням тела, а не по треугольникам |
| [trimesh](https://github.com/mikedh/trimesh) | Всё, что про меши: загрузка STL, герметичность, нормали, лучевые запросы (толщина, внутренние пустоты), правка чужих моделей |
| [manifold3d](https://github.com/elalish/manifold) | Бэкенд булевых операций для trimesh — без него вычитания и объединения на мешах разваливаются |
| [rtree](https://github.com/Toblerity/rtree) | Пространственный индекс, на нём держатся быстрые лучевые запросы trimesh |
| [numpy](https://github.com/numpy/numpy) | Массивы вершин и нормалей, вся геометрическая арифметика в проверках и подсветке свесов |
| [networkx](https://github.com/networkx/networkx) | Граф связности треугольников в `solidify.py`: так находятся внутренние оболочки и кромки, которые потом заклеиваются |
| [Pillow](https://github.com/python-pillow/Pillow) | Обрезка полей у рендеров и сборка видов в один контактный лист |
| [OpenSCAD](https://github.com/openscad/openscad) | Headless-рендер PNG и булев разрез детали. Единственная внешняя программа — остальное пакеты Python |
| [uv](https://github.com/astral-sh/uv) | Зависимости и запуск: `uv run` вместо ручных venv |
| [Claude Code](https://github.com/anthropics/claude-code) | Агент, под которого написан скилл из `skill/` — что вызвать, как прочитать вывод и что править дальше. Формат его, но содержимое обычный markdown: другой агент переучивается на него одной просьбой |

## Зачем, если есть GUI-редакторы

GUI-редактор с MCP заставляет агента кликать в чужом интерфейсе: он не может отдать файл
и не может принять твой STL иначе как массивом координат. Здесь наоборот — файл на входе,
файл на выходе, а между ними текст, который агент читает и правит.

Побочная выгода: параметры детали становятся именованными константами. «Сделай стенку
потолще» — это правка одной строки, а не перерисовывание модели.

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и OpenSCAD.

```bash
git clone git@github.com:StasPotapov/forgeAi3d.git ~/dev/forgeAi3d
cd ~/dev/forgeAi3d
uv sync
```

OpenSCAD на macOS — **именно snapshot-каск**, стабильный `openscad` это сборка 2021.01
под Intel, и macOS ругается на неё:

```bash
brew install --cask openscad@snapshot
```

На Linux — `apt install openscad` или пакет дистрибутива. Инструменты ищут бинарь
`openscad` в `PATH`, на macOS дополнительно смотрят в `/Applications`.

Репозиторий может лежать где угодно: путь берётся от самого пакета, а переопределяется
переменной `FORGEAI3D_HOME`.

## Быстрый старт

```bash
mkdir -p models/fit_test_pla
cp examples/fit_test.py models/fit_test_pla/model.py
uv run python models/fit_test_pla/model.py                                  # -> models/fit_test_pla/
uv run tools/measure.py models/fit_test_pla/fit_test_pla.stl         # размеры и отверстия числами
uv run tools/preview.py models/fit_test_pla/fit_test_pla.stl         # контактный лист
uv run tools/check.py models/fit_test_pla/fit_test_pla.stl --material PLA   # печатать или нет
```

Инструментам достаточно пути к STL: STEP для точного анализа они находят сами.
Отвечают они по-английски — язык у кода и вывода один, независимо от того, на каком
языке идёт разговор с агентом.

`examples/fit_test.py` — калибровочная гребёнка: десять отверстий под M3 с зазорами
от 0.00 до 0.45 мм на сторону. Печатать её необязательно — она нужна, когда типовые
зазоры не сошлись (см. «Калибровка зазоров» ниже).

## Настройка под свой принтер

Встроенные значения **`forge/spec.py`** — Bambu Lab A1 mini и PLA + PETG.
Следующий код показывает эти значения; установленный runtime не редактируют.

```python
A1_MINI = Printer(
    name="Bambu Lab A1 mini",
    bed=(180.0, 180.0, 180.0),
    nozzle=0.4,
    extrusion_width=0.42,   # ширина линии периметра
    layer_height=0.2,
    enclosed=False,         # нет закрытой камеры -> ABS/ASA не поедут
    hardened_nozzle=False,  # нет закалённого -> абразивные не поедут
    ams=False,
    bed_slinger=True,       # стол ездит по Y -> высокие детали качает
)

AVAILABLE = ("PLA", "PETG")   # что реально лежит на полке
```

Свой принтер задавай в `[printer]`, доступные материалы — в `available` личного
`forge-profile.toml`; порядок — в [setup](skills/setup/SKILL.md). Нужны только поправки.
Явный `FORGEAI3D_PROFILE` имеет приоритет. Иначе файл ищется в `FORGEAI3D_HOME`,
при его отсутствии — в `FORGEAI3D_MODEL_DIR`, иначе — в текущей папке.
При смене модели сохраняй HOME корнем воркспейса. Если неявного профиля нет,
используются встроенные значения.

## Как этим пользуются модели

Вместо магических чисел — вызовы из `forge`:

```python
from forge import clearance, wall, compensate_shrink, export_all

MAT = "PETG"
shaft_hole = 8 + 2 * clearance(MAT, "slip")   # 8.6 мм; на PLA было бы 8.4
case_wall  = wall(3)                          # 1.26 мм = 3 периметра, а не «1.5 мм»
length     = compensate_shrink(150, MAT)      # 150.9 мм с поправкой на усадку

export_all(part.part, "деталь", material=MAT) # stl + step + 3mf, запись проверена
```

Типы посадки: `press` (запрессовка), `snug` (с усилием руки), `slip` (свободно ходит),
`free` (заведомо с люфтом). Зазор задаётся **на сторону**, отверстие получает удвоенный.

Помимо PLA и PETG в справочнике заведены `PLA-CF`, `ASA` и `TPU` — чтобы `supported()`
называл причину, когда материал не подходит принтеру (ASA без закрытой камеры, PLA-CF
без закалённого сопла), а не выдумывал зазор молча.

Размеры чужого железа, которые нельзя обмерить руками, ищутся в datasheet и кладутся
в кэш вместе с источником — число без ссылки не сохраняется:

```python
from forge import get_spec, save_spec
save_spec("raspberry pi 5", {"length": 85.0, "width": 56.0},
          source="https://datasheets.raspberrypi.com/rpi5/raspberry-pi-5-mechanical-drawing.pdf")
```

## Что появляется на выходе

Всё для модели хранится в одной личной папке: `model.py`, `README.md`, выбранный
`design.png`, STL, настроенный проект слайсера 3MF и входные файлы в `assets/`.
`export_all` кладёт STL рядом с исходником; STEP, геометрический 3MF, превью и
отчёты — в `extras/`. Настроенный 3MF в корне экспорт CAD не перезаписывает.

## tools/measure.py

Отвечает на вопрос «получилось ли то, что просили» числами, а не картинкой.

```bash
uv run tools/measure.py models/part/part.stl
uv run tools/measure.py models/part/part.stl --json
```

Печатает габариты, объём, число тел и разбор круглых элементов: отверстия с диаметром,
глубиной и координатами центров, штыри, скругления и галтели. Одинаковые схлопываются
в `4 × Ø3.40`. Отверстие называется сквозным по геометрии, а не по габариту детали —
фаска или выступающая надпись сдвигают габарит и путают такую проверку.

## tools/preview.py

Рендерит STL в PNG через headless OpenSCAD и собирает виды в один контактный лист.
Нужен, чтобы агент посмотрел на результат до того, как отдать файл.

```bash
uv run tools/preview.py models/part/part.stl                        # iso, top, front, right
uv run tools/preview.py models/part/part.stl --overhangs --material PETG
uv run tools/preview.py models/part/part.stl --section y            # или y:12.5
uv run tools/preview.py models/part/part.stl -o /tmp/p.png --size 800
```

Без `-o` картинка ложится в `extras/` этой детали, имя получает суффикс режима.
`--size` задаёт разрешение рендера: готовый кадр обрезается по детали, поэтому
тайл выходит меньше запрошенного.

Виды: `iso`, `iso2`, `iso3`, `iso4` (изометрия с четырёх сторон), `top`, `front`,
`right`, `back`, `iso_low`, `bottom`.

`--overhangs` красит красным всё, что придётся поддерживать, и сам переключается
на нижние ракурсы — сверху свесы не видно.

`--section` разрезает деталь и показывает внутренности: толщину стенки иначе
не проверить, не напечатав деталь. Плоскость среза красится оранжевым, а ракурсы
берутся со стороны отрезанной половины — иначе в кадре целая деталь.

## tools/check.py

Проверяет деталь перед печатью.

```bash
uv run tools/check.py models/part/part.stl --material PETG
uv run tools/check.py models/part/part.stl --nozzle 0.6 --bed 256x256x256
uv run tools/check.py models/part/part.stl --no-orientation    # пропустить подбор позы
```

Геометрию считает [augura](https://github.com/pzfreo/augura) — по точным граням тела,
а не по треугольникам: свесы, мосты, толщина стенок, опрокидывание, brim, влезает ли
на стол, минимальная вертикальная ступенька (она же максимальная высота слоя). Плюс
перебирает позы и предлагает ту, где неподдержанных свесов меньше.

По толщине augura отдаёт минимум, а браком деталь становится по **доле поверхности**
тоньше двух периметров: у фаски, уклона и у кромки выдавленной буквы толщина по
построению стремится к нулю, и по одному минимуму в брак уходила бы любая деталь
с надписью. Минимум остаётся в отчёте справкой.

Если на входе STL, рядом ищется одноимённый STEP и анализ идёт по нему. Без STEP
проверка приблизительная: **толщина стенок и мелкие детали по мешу не считаются**,
и отчёт об этом честно говорит.

Качество самого меша (герметичность, нормали, вырожденные треугольники, число тел)
проверяется по STL — это то, чего в STEP не бывает по определению.

**Код возврата 1** — печатать не стоит: негерметичный меш, тонкая стенка, деталь
опрокинется, не влезает на стол ни в одной ориентации, материал несовместим с принтером.
Если деталь влезает после поворота на 90° в плоскости стола, это предупреждение,
а не отказ: augura меряет габарит по осям как есть, а на стол кладут как удобно.

**Предупреждения на код возврата не влияют** — они зависят от ориентации детали,
а её выбирают уже в слайсере: свесы, brim, рекомендация развернуть.

## tools/solidify.py

Заливает внутреннюю полость в чужом меше. Полая модель (труба, вазовый режим,
отсканированная скорлупа) печатается пустой: слайсер честно видит полость и не кладёт
внутрь инфилл.

```bash
uv run tools/solidify.py присланная.stl              # показать, что внутри
uv run tools/solidify.py присланная.stl --fill 1     # -> models/присланная_solid/
```

Сначала инструмент показывает найденные пустоты — сколько треугольников, площадь,
габарит и сколько у пустоты открытых рёбер (`open edges`; ноль означает замкнутую
полость):

```
katana_orig.stl: 5161 mm³, internal voids found: 1
  [1]  1496 triangles, area   4013.6 mm², size 11.2×9.7×168.8 mm, open edges 42
```

**Что заливать, решает человек.** Отличить полость от сквозного отверстия
автоматически нельзя: по лучу стенка отверстия выглядит такой же внутренней, а у
трубы полость сама открыта торцом. Поэтому без `--fill` файл не пишется вовсе —
инструмент не станет молча закрывать отверстия под винты.

Выбранная оболочка срезается, кромка заклеивается веером от центроида. Внешняя
геометрия не трогается — берутся ровно исходные треугольники наружной поверхности,
поэтому профиль и острые рёбра сохраняются 1:1.

## tools/compare.py

Меряет, насколько один меш отличается от другого: деталь до и после правки,
перемоделированную деталь против STL, с которого её снимали, результат `solidify.py`
против исходника.

```bash
uv run tools/compare.py эталон.stl новая.stl              # числа
uv run tools/compare.py эталон.stl новая.stl --heatmap    # + картинка в extras/
uv run tools/compare.py эталон.stl новая.stl --tol 0.1 --json
```

Расстояние меряется в обе стороны, потому что стороны отвечают на разные вопросы:
*reference → candidate* показывает поверхность, которую новая версия потеряла,
*candidate → reference* — поверхность, которой у эталона не было. Для каждой стороны —
среднее, 95-й перцентиль, максимум с координатами и доля площади в пределах `--tol`
(по умолчанию 0.05 мм); затем расстояние Хаусдорфа (худший из двух максимумов)
и симметричное среднее Chamfer.

```
reference: part.stl  6.00×6.00×12.25 mm, 181 mm³
candidate: part_revised.stl  6.00×6.00×12.25 mm, 188 mm³ (+3.4%)
  reference → candidate: mean 0.013, p95 0.079, max 0.200 mm at (-1.99, 2.11, 9.83); 89.8% within 0.05 mm
  candidate → reference: mean 0.018, p95 0.165, max 0.200 mm at (-2.35, 2.03, 1.16); 86.6% within 0.05 mm
hausdorff 0.200 mm, chamfer 0.015 mm
```

`--heatmap` раскрашивает новую версию: серым — в пределах допуска, красным — где материал
добавился, синим — где убрался, по три оттенка (`tol`–4·`tol`, до 16·`tol`, дальше). Для
знака эталон должен быть замкнутым; у открытого красится только расстояние.

Выравнивания нет: меши сравниваются в своих координатах. Если габаритные коробки почти
не пересекаются, инструмент предупредит, что меряет смещение, а не форму.

## Скилл для агента

Скилл учит агента работать по этому циклу: сверять размеры числами, обязательно смотреть
на превью, гонять проверку перед выдачей, брать зазоры из `forge`, а не выдумывать, искать
размеры чужого железа в datasheet вместо того чтобы их сочинять, и править константу вместо
пересборки модели. Внутри — шпаргалка по API build123d и bd_warehouse (каждый пример
исполнен, а не написан по памяти) и правила проектирования под FDM.

**Плагином Claude Code** — английский скилл и скилл установки одной командой:

```
/plugin marketplace add StasPotapov/sp-tools
/plugin install forgeAi3d@sp-tools
```

Затем скажите «настрой forgeAi3d» (или вызовите `/forgeAi3d:setup`). Скилл проверит uv и OpenSCAD
и после согласия поставит их, использует установленный runtime и отдельный проект
моделей `FORGEAI3D_HOME`, вынесет среду uv за пределы пакета, сохранит параметры
принтера и филаментов в `forge-profile.toml` и прогонит тестовую деталь
через все четыре инструмента. Модели, печать и зазоры остаются в воркспейсе при обновлении плагина.
Скилл тогда называется `/forgeAi3d:forgeAi3d`.

**Из клона.** Скилл лежит в двух вариантах, содержание одинаковое: `skill/en/forgeAi3d`
(английский) и `skill/ru/forgeAi3d` (русский). Ставится один — тот, на языке которого удобнее читать:

```bash
ln -s ~/dev/forgeAi3d/skill/en/forgeAi3d ~/.claude/skills/forgeAi3d   # или skill/ru/forgeAi3d
```

Дальше он подхватится сам по контексту или вызывается как `/forgeAi3d <что нужно>`.

**Формат — Claude Code, но привязки к нему нет.** Внутри обычный markdown: инструкции,
таблицы и справочники. Работаешь с другим агентом — попроси его переписать `SKILL.md`
и `references/` в тот формат, который он понимает; правила и числа переедут как есть,
поменяется только обёртка. Примеры установки и вызова в этом файле — под Claude Code.

Скилл универсален: конкретное железо он берёт из `forge/spec.py`, а не из своего текста.

## Калибровка зазоров — можно не делать

Зазоры в `forge/spec.py` — типовые значения, которые работают у большинства. Начинать
с калибровки не надо: печатай деталь, и если посадки сходятся — тема закрыта.

Калибровка нужна, когда одно и то же повторяется: винты входят туго на каждой детали,
или наоборот всё болтается. Тогда дело не в модели, а в том, что твоя связка
«принтер + катушка + профиль» печатает отверстия не так, как заложено в справочнике.

<details>
<summary><b>Зачем это, что даст и как делается</b> — развернуть</summary>

<br>

**Почему числа вообще нужны.** Отверстие печатается меньше номинала: слой кладётся
по хорде, а остывающий пластик тянет края внутрь. Поэтому под винт M3 никто не рисует
3.00 мм — рисуют 3.00 плюс зазор. Насколько именно больше, зависит от температуры,
скорости, охлаждения, влажности катушки и даже от партии пластика, поэтому одного
универсального числа не существует.

**Готовой библиотеки с этими числами нет.** Есть справочные диапазоны в статьях
и онлайн-калькуляторы, но все они дают ту же вилку 0.1–0.3 мм, что уже лежит
в `forge/spec.py`. Единственный способ получить своё число — напечатать и померить.

**Что это даст.** Четыре посадки (`press`, `snug`, `slip`, `free`) начнут означать
именно то, что написано: запрессовка будет держать, а «свободно ходит» перестанет
болтаться. Раз откалибровав, ты правишь один файл, и все будущие детали считают
зазоры уже по своим числам.

**Как это делается.** Гребёнка `examples/fit_test.py` — пластина с десятью отверстиями
под винт M3, у которых зазор растёт с шагом 0.05 мм на сторону: отверстие N имеет
зазор `0.05 * N`, диапазон 0.00–0.45 покрывает все четыре посадки.

1. скопировать `examples/fit_test.py` в отдельную личную папку выбранного пластика
   (для PLA использовать `models/fit_test_pla/model.py`), затем поменять `MAT` в личном `model.py` (материал выдавлен на самой
   детали и попадает в имя файла — гребёнки разных пластиков не перепутаются);
2. запустить этот личный `model.py` (для PLA: `uv run python models/fit_test_pla/model.py`) и напечатать результат;
3. вставить винт M3 по очереди в каждое отверстие и найти два номера: где винт идёт
   с усилием руки — это `snug`, и где ходит свободно, но без люфта — это `slip`;
4. вписать `0.05 * N` этих отверстий в `[materials.PLA.clearances]` (или нужный
   материал) в `forge-profile.toml` проекта моделей.
   `press` обычно на 0.05–0.10 меньше `snug`, `free` — на 0.15 больше `slip`.

Печатать гребёнку нужно тем же профилем, которым потом печатаются детали: другая
высота слоя или скорость — другие числа.

**Тот же тест есть в слайсере.** В OrcaSlicer это встроенная модель:
Prepare → правый клик по столу → Add Handy Model → Tolerance Test, шестигранник
и отверстия с зазорами 0.0–0.4 мм —
[описание в вики](https://www.orcaslicer.com/wiki/calibration/tolerance_calib).
Он отвечает на тот же вопрос; гребёнка отсюда удобнее тем, что меряет под конкретный
винт M3 и сразу даёт числа в том виде, в каком они лежат в `forge/spec.py`.

Если решаешь калибровать всерьёз, разумный порядок — сначала поток и давление в сопле
([календарь калибровок OrcaSlicer](https://www.orcaslicer.com/wiki/guides/calibration_guide)),
и только потом зазоры: перелив меняет размер отверстия сильнее, чем любая посадка.

## Чем это отличается от MCP-серверов для CAD

Рядом живут [build123d-mcp](https://github.com/pzfreo/build123d-mcp),
[agentcad](https://github.com/jdilla1277/agentcad) и
[cad-agent](https://github.com/Svetlana-DAO-LLC/cad-agent) — они дают агенту CAD-сессию
и набор инструментов внутри неё.

forgeAi3d устроен иначе:

- **деталь — самодостаточная личная папка**, а не состояние сессии. Она хранится
  локально; к ней можно вернуться через полгода и поменять одну константу;
- **профиль принтера — исполняемый код**, а не абзац в инструкции. `wall(3)` знает
  ширину линии, `clearance()` знает пластик, `supported()` знает, что ASA здесь не поедет;
- **цикл не заканчивается экспортом**. Самая частая работа — «напечатал, отверстие мало»,
  и она описана в скилле отдельно.

Ничто не мешает пользоваться и тем и другим: MCP-сервер — для лепки геометрии в диалоге,
forgeAi3d — когда деталь нужно хранить, повторять и допиливать по итогам печати.

## Структура

```
examples/  публичные шаблоны, копируются в личную папку модели
models/    личные папки: код, ассеты, референсы и файлы печати (Git-ignore)
forge/     параметры принтера, справочник филаментов, экспорт, кэш найденных размеров
tools/     preview.py — рендер, check.py — проверка, measure.py — обмер, solidify.py — заливка полостей,
           compare.py — расхождение двух мешей
skill/     скилл для агента: en/ и ru/, содержание одинаковое
```

## Личные папки моделей

Личные модели — локальные рабочие данные, а не исходники инструмента. До создания
модели проверь, что `/models/` исключён через Git-ignore родительского воркспейса.
Никогда не добавляй в Git, не коммить, не пушь и не включай в пакет личный код модели,
референсы, профили слайсера и результаты. Общие правила коммитов относятся к коду
самого инструмента, а не к этим папкам. Публичные шаблоны инструмента лежат в
`examples/`; пользовательские модели туда и в общий `docs/` не попадают.

Одна модель — одна самодостаточная папка:

```
models/деталь/
    model.py                 # редактируемый исходник, пути к ассетам от __file__
    README.md                # размеры, пересборка, настройки и ограничения
    design.png               # один выбранный референс, если он есть
    деталь.stl               # геометрия для печати
    деталь.3mf               # настроенный проект слайсера, если подготовлен
    assets/                  # SVG, исходные меши, профили и остальные входные файлы
    extras/                  # STEP, геометрический 3MF, превью, отчёты и прежние версии
```

Начинай доработку с выбранной папки: прочитай README и исходник, посмотри референс.
Всё относящееся к модели хранится здесь. Экспортируй через
`export_all(..., out=Path(__file__).resolve().parent)`, чтобы перемещённая модель
пересобиралась рядом с кодом. `out` — папка модели: STEP и геометрический 3MF идут
в `extras/`; настроенный 3MF в корне экспорт CAD не перезаписывает.
`FORGEAI3D_HOME` может указывать на папку модели или родительский воркспейс;
`FORGEAI3D_MODEL_DIR` явно выбирает папку модели. Без них используется текущая папка:
если в ней есть `model.py`, экспорт остаётся в ней; из родительского воркспейса —
в `models/<имя>/`. Runtime и venv хранятся отдельно от личных данных. В папке
установленного пакета не работай. Кэш обмеров модели — `extras/specs_cache.json`;
необходимые профили также копируй внутрь папки.

При миграции сначала сохрани резервную копию, перенеси вместе входные файлы и
результаты, поправь относительные пути, сверь хеши и пересборку, затем убери старые
разрозненные места. Не выдумывай отсутствующий CAD-исходник присланного STL:
честно пометь модель как mesh-only. Не подменяй настроенный 3MF геометрическим.
После изменения геометрии заново выполни слайсинг, проверь один экземпляр, если
не просили другое, сохрани принтер, материал, пластину и настройки процесса.

## Переносимый runtime

При установке через AI Workspace храните закреплённый runtime отдельно от проектов
моделей. `FORGEAI3D_HOME` указывает на проект модели; его `forge-profile.toml`
(или `FORGEAI3D_PROFILE`) задаёт принтер и поправки материалов. Среду uv вынесите
из пакета через `UV_PROJECT_ENVIRONMENT`. Порядок — в `skills/setup/SKILL.md`;
обновляйте пакет через workspace, не редактируйте snapshot и не делайте в нём git pull.
