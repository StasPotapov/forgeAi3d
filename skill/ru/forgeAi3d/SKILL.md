# forgeAi3d — моделирование под 3D-печать

Код-CAD: деталь это Python-файл на build123d, из него падают STL для печати, STEP для
дальнейших правок и точного анализа, 3MF для Bambu Studio. Модель — текст, значит её
видно целиком, правки точечные, история сохраняется.

**Всё живёт в корне репозитория** — `$FORGEAI3D_HOME`, по умолчанию `~/dev/forgeAi3d`.
Исходники в `models/`, экспорт в `prints/`, справочник принтера и филаментов в `forge/`,
инструменты в `tools/`. Подробности — `README.ru.md` в корне.

**Инструменты и код отвечают по-английски** — так же, как любая библиотека. Читай их
вывод как есть, а пользователю пересказывай по-русски.

**У каждой детали своя папка в `prints/`.** На виду лежит только STL — его несут в
слайсер; STEP, 3MF, превью и разрезы убраны в `extras/`, чтобы не мешались:

```
prints/подставка/
    подставка.stl                     ← это отдаётся пользователю
    extras/подставка.step             ← правки и точный анализ
    extras/подставка.3mf              ← Bambu Studio
    extras/подставка.png              ← превью
    extras/подставка-overhangs.png    ← свесы
    extras/подставка-section-y.png    ← разрез
```

Раскладку делает `export_all`, инструменты принимают путь к STL и остальное находят
сами. Руками пути в `extras/` собирать не нужно.

**Принтер и наличные пластики описаны в `forge/spec.py` — читай оттуда, а не по памяти.**
Сейчас там Bambu Lab A1 mini (стол 180×180×180, сопло 0.4, без закрытой камеры,
без закалённого сопла) и пластики PLA + PETG. Сменится железо или катушки — правится
там же, модели и проверки подхватят новое сами.

## Цикл

```
понять задачу → models/деталь.py → measure (числа) → preview (глаза) → check → отдать
                       ↑                                                        ↓
                       └──────────── правка константы ←── «отверстие мало» ──────┘
```

```bash
cd "${FORGEAI3D_HOME:-$HOME/dev/forgeAi3d}"
uv run python models/деталь.py                       # -> prints/деталь/деталь.stl + extras/
uv run tools/measure.py prints/деталь/деталь.stl        # размеры и отверстия числами
uv run tools/preview.py prints/деталь/деталь.stl        # -> extras/деталь.png
uv run tools/check.py prints/деталь/деталь.stl --material PETG   # exit 1 = печатать нельзя
```

## Обязательные правила

**Сначала числа, потом глаза.** `measure.py` печатает габариты, объём и инвентарь
отверстий — диаметр, глубина, «through» у сквозных, координаты центров. Сверься с тем, что просили,
до рендера: картинка выглядит правильной и при неверной геометрии.

**Потом всё равно посмотри на превью сам.** После рендера открой PNG через Read. Без
этого нельзя отдавать результат: числа не ловят «ребро торчит не туда», а `check.py` —
«отверстие не в той стенке».

**Гоняй `check.py` всегда.** Не отдавай файл, пока он не вернул 0 или пока не объяснил
пользователю, почему предупреждение здесь нормально.

**Никаких магических чисел.** Зазоры и толщины — только через `forge`:

```python
from forge import clearance, wall, compensate_shrink
hole = 8 + 2 * clearance(MAT, "slip")   # не 8.6
t    = wall(3)                          # не 1.26
```

**Параметры — константами вверху файла**, с комментарием откуда взялись. Тогда правка
по итогам печати это одна строка, а не пересборка модели:

```python
MAT       = "PETG"
PHONE_W   = 78.0    # обмерено штангенциркулем, iPhone в чехле
WALL      = wall(3)
```

**Экспорт — через `export_all`**, он пишет все три формата и проверяет запись:

```python
from forge import export_all
paths = export_all(part.part, "деталь", material=MAT)
```

**Имена файлов совпадают:** `models/подставка.py` → `prints/подставка/подставка.stl`.
`check.py` и `measure.py` сами подхватят STEP из `extras/` и проверят по нему точно.

## Размеры чужого железа не выдумываются

Габарит платы, диаметр объектива, шаг крепёжных отверстий — это факты, а не оценки.
Ошибка здесь не видна ни на превью, ни в проверке: деталь получится аккуратной
и не подойдёт.

Порядок действий:

1. **попроси обмерить** — если предмет у пользователя в руках, это точнее любого
   datasheet: назови, какие именно три числа нужны;
2. **посмотри в кэше** — `forge.get_spec("raspberry pi 5")` вернёт то, что уже находили;
3. **поищи** — WebSearch по datasheet или официальной документации, и запиши:

```python
from forge import get_spec, save_spec
save_spec("raspberry pi 5", {"length": 85.0, "width": 56.0, "hole_pitch_x": 58.0},
          source="https://datasheets.raspberrypi.com/rpi5/raspberry-pi-5-mechanical-drawing.pdf")
```

Число без источника не сохраняется — `save_spec` этого не позволит. В самой модели
рядом с константой оставляй комментарий, откуда она.

Если найти не удалось — скажи об этом прямо и предложи обмерить. Не подставляй
правдоподобное.

## Что спрашивать, а что решать самому

Спрашивай только то, без чего деталь получится неправильной:

- **размеры физического объекта**, к которому деталь крепится (см. выше);
- **материал**, если он меняет конструкцию (нагрев, нагрузка, гибкость). Иначе бери PLA
  и скажи об этом вслух;
- **как деталь нагружена** — если от этого зависит толщина и рёбра.

Решай сам и назови решение в ответе: скругления, фаски, толщина стенок, ориентация,
шаг сетки отверстий, эстетика. Не устраивай интервью на пять вопросов ради подставки.

## Готовый крепёж — из bd_warehouse

Винты, гайки, шайбы, подшипники, шестерни и резьбы не моделируются руками: их размеры
берутся из `bd_warehouse` по стандарту. Зазор к ним всё равно добавляется из `forge` —
у библиотеки посадки машиностроительные, не под FDM. Примеры — в
`references/build123d.md`.

## Правка чужих моделей

Что прислали определяет, что можно сделать:

| Формат | Что делать |
|---|---|
| **STEP** | `import_step()` — полноценное тело, режется и правится в build123d как своё |
| **STL** | геометрию не восстановить. Мелкие правки — trimesh (масштаб, поворот, разрез, булево, починка). Серьёзные — перемоделировать с нуля по обмерам, честно сказав об этом |

`import_stl()` в build123d возвращает `Face`, а не тело — булевы операции с ним не пройдут.
Для мешей только trimesh (`manifold3d` уже стоит, булевы работают). Подробности —
`references/build123d.md`.

**Полая модель, которая должна быть сплошной** — `tools/solidify.py`: срезает внутреннюю
оболочку, заклеивает кромку, отдаёт тело, которое слайсер заполнит инфиллом. Внешняя
геометрия не трогается.

Работает в два шага: сперва показывает найденные пустоты, потом заливает выбранные.
Без `--fill` файл не пишется. Отличить полость от сквозного отверстия автоматически
нельзя, поэтому **выбор за человеком**: покажи пользователю список и спроси, что
заливать, а не решай сам. Подсказки в списке — «open edges 0» означает замкнутую
полость, а «size» вида 3.9×3.9×5.2 мм выдаёт отверстие под винт.

```bash
uv run tools/solidify.py присланная.stl                        # список пустот
uv run tools/solidify.py присланная.stl --fill 1     # -> prints/присланная_solid/
```

**Никогда не перезаписывай присланный файл.** Результат — новый файл в `prints/`.

## Когда деталь непечатаема

`check.py` считает геометрию через augura по STEP — точно, по граням, а не по
треугольникам. Что он говорит и что с этим делать:

Находки инструмент называет по-английски — в таблице они в том же виде, в каком приходят:

| Находка | Что менять |
|---|---|
| `thin wall` | `wall(3)` вместо `wall(2)`. Отказ, когда тонкая заметная доля поверхности; про одну кромку фаски или надписи он скажет предупреждением |
| `overhang` | развернуть деталь, заменить свес фаской 45°, отверстие сделать каплей |
| `will tip over` | brim, печать набок или расширить основание |
| `brim needed` | сказать пользователю, это не дефект модели |
| `lay it differently` | предложенный поворот — рекомендация augura, решай вместе с пользователем |
| `the smallest step … is thinner than the … layer` | мелкая деталь пропадёт: увеличить её или печатать слоем мельче |

Посмотреть, **где** свесы: `uv run tools/preview.py prints/деталь/деталь.stl --overhangs
--material PETG` — красным. Посмотреть внутрь: `--section y` (разрез посередине, можно
`y:12.5`). Картинки лягут в `extras/` рядом с деталью.

Самая долгая часть проверки — перебор поз. На крупной детали, когда ориентация уже
решена, его можно пропустить: `--no-orientation`.

## Итерации по результату печати

Пользователь печатает и говорит, что не так. Это самая частая работа.

| Что сказал | Что менять |
|---|---|
| «винт не входит» / «болтается» | тип посадки в `clearance()`, не само число |
| «слишком хлипко», «сломалось» | `wall(3)` → `wall(4)`, галтели в углах, рёбра жёсткости |
| «не влезло на стол» | разбить на части с замком, или развернуть |
| «низ поплыл, размер не сошёлся» | elephant foot — фаска 0.5 мм по нижнему контуру |
| «поддержки не отодрать» | сменить ориентацию или переделать свес под 45° |

Меняй **константу**, пересобирай, показывай превью, говори что именно поменялось.
Если правка вскрывает системную ошибку в зазорах — предложи откалибровать:
`uv run python models/fit_test.py`, напечатать гребёнку, вписать реальные числа
в `clearances` нужного материала в `forge/spec.py`. Не создавай для этого новый файл —
`models/fit_test.py` уже есть.

## Что отдавать пользователю

1. **путь к STL — всегда и первой строкой.** Полный путь вида
   `prints/подставка/подставка.stl`, а не «файл в prints» и не путь к папке: этот файл
   человек сейчас потащит в слайсер. Пути к STEP, 3MF и превью — только если
   спросили или если они нужны для дела;
2. превью (покажи, что сам смотрел),
3. итог `check.py` одной строкой,
4. **какие константы крутить** и что они меняют,
5. рекомендации по печати, если они неочевидны: ориентация, поддержки, brim.

## Границы

Скажи честно, когда задача не для этого стека:

- органика и скульптура — это Blender, не build123d;
- точная ответственная посадка требует калибровки, до неё зазоры типовые;
- материал, который принтер не тянет (ASA без камеры, PLA-CF без закалённого сопла), —
  `check.py` скажет это сам, исходя из профиля в `forge/spec.py`;
- резьбу лучше нарезать метчиком или поставить термовставку, чем печатать;
- по мешу без STEP толщина стенок и мелкие детали не проверяются — скажи об этом,
  когда отдаёшь результат правки чужого STL.
