# forgeAi3d — моделирование под 3D-печать

Runtime ищи в полном пакете forgeAi3d, три уровня выше этого скилла; его `forge/`, `tools/` и зависимости не являются папкой личных моделей.
Прочитай `forge/spec.py` для параметров принтера; настройка зависимостей — `skills/setup/SKILL.md`.

## Личные папки моделей

Личные модели — локальные рабочие данные, а не исходники инструмента. До создания
модели проверь, что `/models/` исключён через Git-ignore родительского воркспейса.
Никогда не добавляй в Git, не коммить, не пушь и не включай в пакет личный код модели,
референсы, профили слайсера и результаты. Общие правила коммитов относятся к коду
самого инструмента, а не к этим папкам. Публичные шаблоны инструмента лежат в
`examples/`; пользовательские модели туда и в общий `docs/` не попадают.

Одна модель — одна самодостаточная папка:

```
models/деталь/
    model.py                 # редактируемый исходник, пути к ассетам от __file__
    README.md                # размеры, пересборка, настройки и ограничения
    design.png               # один выбранный референс, если он есть
    деталь.stl               # геометрия для печати
    деталь.3mf               # настроенный проект слайсера, если подготовлен
    assets/                  # SVG, исходные меши, профили и остальные входные файлы
    extras/                  # STEP, геометрический 3MF, превью, отчёты и прежние версии
```

Начинай доработку с выбранной папки: прочитай README и исходник, посмотри референс.
Всё относящееся к модели хранится здесь. Экспортируй через
`export_all(..., out=Path(__file__).resolve().parent)`, чтобы перемещённая модель
пересобиралась рядом с кодом. `out` — папка модели: STEP и геометрический 3MF идут
в `extras/`; настроенный 3MF в корне экспорт CAD не перезаписывает.
`FORGEAI3D_HOME` может указывать на папку модели или родительский воркспейс;
`FORGEAI3D_MODEL_DIR` явно выбирает папку модели. Без них используется текущая папка:
если в ней есть `model.py`, экспорт остаётся в ней; из родительского воркспейса —
в `models/<имя>/`. Runtime и venv хранятся отдельно от личных данных. В папке
установленного пакета не работай. Сохраняй `FORGEAI3D_HOME` корнем воркспейса с
общим профилем; активную модель выбирай через `FORGEAI3D_MODEL_DIR` и `cd`. Для
отдельной самодостаточной папки обе переменные могут указывать на неё.
`FORGEAI3D_PROFILE` явно выбирает файл профиля. Кэш обмеров модели — `extras/specs_cache.json`;
необходимые профили также копируй внутрь папки.

При миграции сначала сохрани резервную копию, перенеси вместе входные файлы и
результаты, поправь относительные пути, сверь хеши и пересборку, затем убери старые
разрозненные места. Не выдумывай отсутствующий CAD-исходник присланного STL:
честно пометь модель как mesh-only. Не подменяй настроенный 3MF геометрическим.
После изменения геометрии заново выполни слайсинг, проверь один экземпляр, если
не просили другое, сохрани принтер, материал, пластину и настройки процесса.

## Цикл

```
понять задачу → models/деталь/model.py → measure (числа) → preview (глаза) → check → отдать
                       ↑                                                        ↓
                       └──────────── правка константы ←── «отверстие мало» ──────┘
```

Геометрию проверяют `measure`, `preview` и `check`. Дополнительное ревью выполняй,
если его требуют правила пользователя; оно не разрешает коммитить личную модель.

```bash
# Resolve both paths first; keep the environment outside the immutable package.
export FORGEAI3D_HOME="<absolute-model-workspace>"
export FORGEAI3D_MODEL_DIR="<absolute-model-folder>"
export FORGEAI3D_RUNTIME="<real-package-root>"
export UV_PROJECT_ENVIRONMENT="${XDG_DATA_HOME:-$HOME/.local/share}/forgeAi3d/venv"
export PYTHONDONTWRITEBYTECODE=1
cd "$FORGEAI3D_MODEL_DIR"
# In commands below, use uv run --frozen --project "$FORGEAI3D_RUNTIME";
# resolve tools/... and forge/spec.py against FORGEAI3D_RUNTIME.
uv run --frozen --project "$FORGEAI3D_RUNTIME" python model.py                       # -> деталь.stl + extras/
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/measure.py" деталь.stl        # размеры и отверстия числами
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/preview.py" деталь.stl        # -> extras/деталь.png
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/check.py" деталь.stl --material PETG   # exit 1 = печатать нельзя
```

## Обязательные правила

**Сначала числа, потом глаза.** `measure.py` печатает габариты, объём и инвентарь
отверстий — диаметр, глубина, «through» у сквозных, координаты центров. Сверься с тем, что просили,
до рендера: картинка выглядит правильной и при неверной геометрии.

**Потом всё равно посмотри на превью сам.** После рендера открой PNG через Read. Без
этого нельзя отдавать результат: числа не ловят «ребро торчит не туда», а `check.py` —
«отверстие не в той стенке».

**Гоняй `check.py` всегда.** Не отдавай файл, пока он не вернул 0 или пока не объяснил
пользователю, почему предупреждение здесь нормально.

**Никаких магических чисел.** Зазоры и толщины — только через `forge`:

```python
from forge import clearance, wall, compensate_shrink
hole = 8 + 2 * clearance(MAT, "slip")   # не 8.6
t    = wall(3)                          # не 1.26
```

**Параметры — константами вверху файла**, с комментарием откуда взялись. Тогда правка
по итогам печати это одна строка, а не пересборка модели:

```python
MAT       = "PETG"
PHONE_W   = 78.0    # обмерено штангенциркулем, iPhone в чехле
WALL      = wall(3)
```

**Экспорт — через `export_all`**, он пишет все три формата и проверяет запись:

```python
from forge import export_all
from pathlib import Path
paths = export_all(part.part, "деталь", material=MAT, out=Path(__file__).resolve().parent)
```

**Имена файлов совпадают:** `models/подставка/model.py` → `models/подставка/подставка.stl`.
`check.py` и `measure.py` сами подхватят STEP из `extras/` и проверят по нему точно.

## Размеры чужого железа не выдумываются

Габарит платы, диаметр объектива, шаг крепёжных отверстий — это факты, а не оценки.
Ошибка здесь не видна ни на превью, ни в проверке: деталь получится аккуратной
и не подойдёт.

Порядок действий:

1. **попроси обмерить** — если предмет у пользователя в руках, это точнее любого
   datasheet: назови, какие именно три числа нужны;
2. **посмотри в кэше** — `forge.get_spec("raspberry pi 5")` вернёт то, что уже находили;
3. **поищи** — WebSearch по datasheet или официальной документации, и запиши:

```python
from forge import get_spec, save_spec
save_spec("raspberry pi 5", {"length": 85.0, "width": 56.0, "hole_pitch_x": 58.0},
          source="https://datasheets.raspberrypi.com/rpi5/raspberry-pi-5-mechanical-drawing.pdf")
```

Число без источника не сохраняется — `save_spec` этого не позволит. В самой модели
рядом с константой оставляй комментарий, откуда она.

Если найти не удалось — скажи об этом прямо и предложи обмерить. Не подставляй
правдоподобное.

## Что спрашивать, а что решать самому

Спрашивай только то, без чего деталь получится неправильной:

- **размеры физического объекта**, к которому деталь крепится (см. выше);
- **материал**, если он меняет конструкцию (нагрев, нагрузка, гибкость). Иначе бери PLA
  и скажи об этом вслух;
- **как деталь нагружена** — если от этого зависит толщина и рёбра.

Решай сам и назови решение в ответе: скругления, фаски, толщина стенок, ориентация,
шаг сетки отверстий, эстетика. Не устраивай интервью на пять вопросов ради подставки.

## Готовый крепёж — из bd_warehouse

Винты, гайки, шайбы, подшипники, шестерни и резьбы не моделируются руками: их размеры
берутся из `bd_warehouse` по стандарту. Зазор к ним всё равно добавляется из `forge` —
у библиотеки посадки машиностроительные, не под FDM. Примеры — в
`references/build123d.md`.

## Правка чужих моделей

Что прислали определяет, что можно сделать:

| Формат | Что делать |
|---|---|
| **STEP** | `import_step()` — полноценное тело, режется и правится в build123d как своё |
| **STL** | геометрию не восстановить. Мелкие правки — trimesh (масштаб, поворот, разрез, булево, починка). Серьёзные — перемоделировать с нуля по обмерам, честно сказав об этом |

`import_stl()` в build123d возвращает `Face`, а не тело — булевы операции с ним не пройдут.
Для мешей только trimesh (`manifold3d` уже стоит, булевы работают). Подробности —
`references/build123d.md`.

**Полая модель, которая должна быть сплошной** — `tools/solidify.py`: срезает внутреннюю
оболочку, заклеивает кромку, отдаёт тело, которое слайсер заполнит инфиллом. Внешняя
геометрия не трогается.

Работает в два шага: сперва показывает найденные пустоты, потом заливает выбранные.
Без `--fill` файл не пишется. Отличить полость от сквозного отверстия автоматически
нельзя, поэтому **выбор за человеком**: покажи пользователю список и спроси, что
заливать, а не решай сам. Подсказки в списке — «open edges 0» означает замкнутую
полость, а «size» вида 3.9×3.9×5.2 мм выдаёт отверстие под винт.

```bash
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/solidify.py" присланная.stl                        # список пустот
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/solidify.py" присланная.stl --fill 1     # -> присланная_solid.stl в открытой папке модели
```

**Никогда не перезаписывай присланный файл.** В открытой папке модели результат —
новый `*_solid.stl` рядом с исходником. Из воркспейса без выбранной модели путь
по умолчанию — `models/<имя>_solid/<имя>_solid.stl`. Другой путь задаётся через `--out`.

**Сверка с оригиналом — `tools/compare.py`.** После перемоделирования чужого STL, после
`solidify.py` и после правки, которая не должна была задеть остальное, сравни новое
со старым числом, а не на глаз:

```bash
uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/compare.py" присланная.stl деталь.stl --heatmap
```

Читай обе стороны: `reference → candidate` — что потерялось, `candidate → reference` —
что появилось. После `solidify.py` первая показывает срезанную внутреннюю оболочку, это
нормально, а вторая должна быть почти вся `within` — кроме заклеенной кромки. Модели
в одних координатах: перемоделированную деталь сначала поставь туда, где лежит оригинал.

## Когда деталь непечатаема

`check.py` считает геометрию через augura по STEP — точно, по граням, а не по
треугольникам. Что он говорит и что с этим делать:

Находки инструмент называет по-английски — в таблице они в том же виде, в каком приходят:

| Находка | Что менять |
|---|---|
| `thin wall` | `wall(3)` вместо `wall(2)`. Отказ, когда тонкая заметная доля поверхности; про одну кромку фаски или надписи он скажет предупреждением |
| `overhang` | развернуть деталь, заменить свес фаской 45°, отверстие сделать каплей |
| `will tip over` | brim, печать набок или расширить основание |
| `brim needed` | сказать пользователю, это не дефект модели |
| `lay it differently` | предложенный поворот — рекомендация augura, решай вместе с пользователем |
| `the smallest step … is thinner than the … layer` | мелкая деталь пропадёт: увеличить её или печатать слоем мельче |

Посмотреть, **где** свесы: `uv run --frozen --project "$FORGEAI3D_RUNTIME" python "$FORGEAI3D_RUNTIME/tools/preview.py" деталь.stl --overhangs
--material PETG` — красным. Посмотреть внутрь: `--section y` (разрез посередине, можно
`y:12.5`). Картинки лягут в `extras/` рядом с деталью.

Самая долгая часть проверки — перебор поз. На крупной детали, когда ориентация уже
решена, его можно пропустить: `--no-orientation`.

## Итерации по результату печати

Пользователь печатает и говорит, что не так. Это самая частая работа.

| Что сказал | Что менять |
|---|---|
| «винт не входит» / «болтается» | тип посадки в `clearance()`, не само число |
| «слишком хлипко», «сломалось» | `wall(3)` → `wall(4)`, галтели в углах, рёбра жёсткости |
| «не влезло на стол» | разбить на части с замком, или развернуть |
| «низ поплыл, размер не сошёлся» | elephant foot — фаска 0.5 мм по нижнему контуру |
| «поддержки не отодрать» | сменить ориентацию или переделать свес под 45° |

Меняй **константу**, пересобирай, показывай превью, говори что именно поменялось.
При системной ошибке зазоров предложи калибровку. Выбери отдельную личную папку:
`<воркспейс>/models/fit_test_pla` для общего воркспейса или соседнюю папку для
самодостаточной модели. Не вкладывай другую модель внутрь активной модели.
Скопируй туда runtime `examples/fit_test.py` как `model.py`, если файла ещё нет.
Запусти `uv run --frozen --project "$FORGEAI3D_RUNTIME" python "<absolute-calibration-folder>/model.py"`.
На время запуска сохрани текущий `FORGEAI3D_HOME` и выбранный профиль. Если используется
файл профиля, перед сменой папок закрепи его абсолютный путь в `FORGEAI3D_PROFILE`.
Напечатай гребёнку и впиши измеренные значения в таблицу `clearances` нужного материала
в этом же личном `forge-profile.toml`.

## Что отдавать пользователю

1. **путь к STL — всегда и первой строкой.** Полный путь вида
   `models/подставка/подставка.stl`, а не «файл в prints» и не путь к папке: этот файл
   человек сейчас потащит в слайсер. Пути к STEP, 3MF и превью — только если
   спросили или если они нужны для дела;
2. превью (покажи, что сам смотрел),
3. итог `check.py` одной строкой,
4. **какие константы крутить** и что они меняют,
5. рекомендации по печати, если они неочевидны: ориентация, поддержки, brim.

## Справочники

- `references/build123d.md` — API-шпаргалка, проверенная на живом коде: примитивы,
  селекторы, отверстия, оболочки, вращение, импорт/экспорт, bd_warehouse, правка мешей, грабли
- `references/design-rules.md` — правила проектирования под FDM: стенки, свесы, отверстия,
  резьба, термовставки, защёлки, ориентация, разбиение крупных деталей

## Границы

Скажи честно, когда задача не для этого стека:

- органика и скульптура — это Blender, не build123d;
- точная ответственная посадка требует калибровки, до неё зазоры типовые;
- материал, который принтер не тянет (ASA без камеры, PLA-CF без закалённого сопла), —
  `check.py` скажет это сам, исходя из профиля в `forge/spec.py`;
- резьбу лучше нарезать метчиком или поставить термовставку, чем печатать;
- по мешу без STEP толщина стенок и мелкие детали не проверяются — скажи об этом,
  когда отдаёшь результат правки чужого STL.
